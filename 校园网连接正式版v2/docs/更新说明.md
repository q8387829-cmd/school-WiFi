# v2.0.0 更新说明

发布日期：2026-11-08。本版更新 PowerShell 恢复调度、状态与界面资源，并整理正式发行目录；原生桌面宿主及进程查询 DLL 保持 v1 的原始二进制。

## 问题证据与结论范围

一次已脱敏的 v1 运行记录显示：

| 时间 | 记录中的事件 |
| --- | --- |
| 2026-11-08 19:33:17 | 检测到系统唤醒。 |
| 19:33:18 | 确认 `Offline` 并发起登录。 |
| 19:33:21 | 登录返回 `LoginUnclassified`，安排 60 秒后重试；同秒出现 `NetworkChanged`。 |
| 19:34:23 | 下一次登录尝试。 |
| 19:34:28 | 复核为在线。 |

该记录支持“唤醒后首次提交未确认恢复，随后约一分钟才再次提交”。旧日志没有 `ManualCheck` 事件，不能据此断言点击操作导致了恢复，也不能证明所有慢恢复都来自同一个原因。本版针对已观察到的长等待与反馈不清晰改进，实际校园网恢复效果仍需要在真实环境中观察。

## 恢复与重试规则

| 条件 | v2 行为 |
| --- | --- |
| 启动、系统唤醒、有效本地网络变化 | 可进入 90 秒恢复观察期，期间通常约每 2 秒采样；普通状态通常约每 5 秒采样。只在确认 `Offline` 且策略允许时提交登录。 |
| 恢复期内临时失败 | 最多使用 3、5、10 秒三次快速重试间隔。不是无限快速重试。 |
| 普通失败或快速预算耗尽 | 按累计失败次数选择 15、30、60、120、300 秒退避，达到上限后保持 300 秒。快速阶段也累计失败，所以退出快速阶段不会承诺从 15 秒重新开始。 |
| 未分类认证拒绝 | 累计到 3 次进入 300 秒安全冷却，到期自动重试；之后继续未分类拒绝，每次仍使用 300 秒。只有在线或账号记录更新才清零累计状态，冷却到期本身不清零。 |
| 明确账号、密码、验证码等需人工处理的错误 | 暂停自动提交，保留状态复查；保存更新的账号记录或检测为在线后解除本轮暂停。唤醒、网络变化和“立即检查”不绕过暂停。 |
| 服务端限流 | 至少等待 60 秒，并尊重可解析的更长 `Retry-After`；更换账号和手动检查也不绕过当前限流期限。 |
| 提交前本地网络尚未就绪 | 等待复查，不计作账号拒绝；状态恢复后再按约束决定是否提交。 |
| 重复网络事件、连续点击 | 新恢复窗口至少间隔 120 秒，事件不会持续延长当前窗口或补满快速预算；手动检查至少间隔 5 秒，仍尊重上次提交至少 3 秒、限流与安全冷却。 |

间隔从相应检查或失败处理时刻计算，HTTP 等待、状态复核和系统调度会增加墙钟时间。90 秒观察期不是联网时限保证；未确认网络状态时不会把它误当作已离线而盲目提交账号。

## 界面与状态

- 增加 `Recovering` 展示和恢复观察倒计时；`RetryWaiting` 显示下一次自动重试倒计时。
- 后台状态提供 `NextAttemptUtc`、`RecoveryUntilUtc`，前端按时间刷新，过期或无法解析的时间不会显示负数或 `NaN`。
- “立即检查”请求成功时保持安静，状态正常更新；失败提示保留。启动与停止监测反馈明确为“已请求”，不把请求确认误写成状态已经完成。
- 页面标识为“正式版 v2”，移除面向开发的“原助手/原后台”文案与不存在的验证模块导入。

## 发行整理

- 根入口转向完整的 `app/` 相对目录；`tools/` 收纳维护与只读检查命令，`docs/` 收纳文档。
- 完整性检查从发行根目录读取 SHA-256 清单，检查缺失、变化、额外文件、危险路径与链接。默认跳过运行数据内容，`-Strict` 拒绝带个人数据目录的发行副本。
- 发行材料保留第三方许可证、WebView2 配套 DLL 和小型进程查询 DLL，不携带旧账号、日志、浏览器缓存、临时诊断和开机启动备份。
- 本版没有安装依赖、自动迁移账号或自动切换正在运行的旧版。第一次启用 v2 的操作仍需按[使用说明](<使用说明.md>)完成。

## 验证范围

静态语法、纯调度逻辑和模拟状态的界面测试可证明所覆盖的代码路径；发行清单与解压复核可证明文件一致性。它们不能代替真实 Windows 桌面启动、实际睡眠/唤醒、校园网认证或服务端限流测试。校验脚本成功也不代表整个程序获得发布者数字签名。
