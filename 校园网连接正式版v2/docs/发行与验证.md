# 发行结构、依赖与验证

## 目录约定

```text
校园网连接正式版v2/
├─ 打开校园网助手.cmd          常用入口
├─ 打开校园网助手.vbs          隐藏 PowerShell 启动入口
├─ check-release.cmd           只读环境与完整性检查
├─ README.md
├─ release.json
├─ 文件清单.sha256             发布完成后生成，不列入自身
├─ app/
│  ├─ CampusNetwork*.ps1       认证、监测、诊断和设置脚本
│  ├─ 打开校园网助手.vbs       应用内部与开机启动使用的入口
│  ├─ CampusNetwork-Lens/
│  │  ├─ CampusNetwork.Lens.exe
│  │  ├─ CampusNetwork.ProcessQuery.dll
│  │  ├─ Microsoft.Web.WebView2.*.dll
│  │  ├─ WebView2Loader.dll
│  │  ├─ Start-Lens.ps1、Runtime-Lens.ps1
│  │  ├─ backend/、web/        后台桥接和完整本地界面资源
│  │  └─ state/               运行生成，不随发行包分发
│  └─ data/                   运行生成，不随发行包分发
├─ tools/                     维护命令和只读检查
└─ docs/                      使用、迁移、更新、发行说明
```

所有入口使用自身位置解析相对路径；v2 不依赖 v1 安装位置。`app/` 内部的层级不能任意改名或拆分：宿主读取界面与后台，后台再相对定位应用脚本和数据。程序启动时发布到 LocalAppData 的 EXE 仍需要原发行目录，不能将该缓存中的 EXE 视为独立成品。

## 个人数据与分发清理

发布时应只收集明确的程序、依赖、工具、文档与许可文件。以下项目不进入对外发行包：`app/data/`、`app/CampusNetwork-Lens/state/`、账号文件、日志、临时诊断、开机启动备份、构建或测试残留。

旧账号属于个人配置，不是可直接删除的垃圾；v1 原目录应保持不动。浏览器缓存和临时文件可在对应实例彻底退出后按需清理，但不要据此删除程序 SDK、进程查询 DLL 或第三方资源。制作本包不负责清理正在运行副本的目录。

## 完整性检查

直接使用 Windows PowerShell 5.1 执行：

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tools\Check-Environment.ps1
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tools\Verify-Release.ps1
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\tools\Verify-Release.ps1 -Strict
```

完整性工具从发行根目录读取清单。每行是 64 位 SHA-256、两个空格、相对路径；清单覆盖其余所有发行文件，不列入自身。工具拒绝越界、绝对路径、重复路径、替代数据流、非法路径分量以及文件树中的符号链接或目录联接；核对缺失、改动和未登记常规文件。

默认模式不遍历或读取 `app/data/` 与 `app/CampusNetwork-Lens/state/` 的内容，适合已使用的副本；`-Strict` 连这两个目录的存在也视为失败，适合干净发行和解压复核。工具只读，不修复或删除文件。清单不是发布者签名；若攻击者同时替换文件与清单，哈希一致也不能证明来源可信。

生成最终压缩包前应在所有改动稳定后更新清单，执行严格检查；压缩后在另一个干净位置解压，复查每个相对路径、文件数、哈希与禁止分发的目录。之后修改任何发行文件都必须重新生成清单和压缩包。

## 验证分层与未验证事项

1. **静态检查**：使用 Windows PowerShell 5.1 的实际文件解析器检查所有脚本，中文脚本保留 UTF-8 BOM；检查 JavaScript 语法、本地模块引用、启动器相对路径与版本元数据。只解析，不运行认证脚本。
2. **纯逻辑检查**：对恢复窗口、快速重试预算、普通退避、未知拒绝累计冷却、明确账号暂停、限流、手动复查与倒计时使用合成状态验证，不读取真实账号、不访问校园网。
3. **发行检查**：生成清单、严格校验、压缩、干净解压后再次严格校验，并确认五个原生/SDK文件与既有来源相符。
4. **实际启动检查**：在隔离测试用户、虚拟机或其他明确受控环境，用不带账号和开机启动配置的干净副本测试窗口、托盘、页面和后台连接。不要为测试而启动现有含账号副本；默认自动监测可能发起认证。应用启动仍可能读取网络状态，不应把启动测试称为完全无网络操作。
5. **校园网验收**：真实认证、睡眠/唤醒、DHCP/链路切换、服务器拒绝及限流需在用户允许的真实网络条件下验证，并保留脱敏结果。

静态和模拟测试不能替代后两层。v1 附带的 `-Fixture` / UI 验证入口引用的测试资源并不完整，不应把运行这些入口失败当作正常发行启动失败，也不能据此声称完成端到端测试。本次已去除缺失 UI 验证模块的动态导入，保留正常界面行为。
