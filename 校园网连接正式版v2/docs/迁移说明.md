# 从 v1 迁移与回退

v2 目录可独立存在，不会在打开时自动导入 v1 账号。制作发行包没有迁移、解密或打印账号，也没有停止正在运行的 v1 或改动它的开机启动。本说明中的操作由使用者在准备切换时执行。

## 推荐：重新输入账号

1. 完整解压并校验 v2，保留 v1 原目录作为回退副本。
2. 在 v1 暂停自动监测，然后通过托盘彻底退出；关闭窗口通常仍会驻留，不能视为退出。
3. 打开 v2，在“账号与设置”重新输入账号、运营商和密码，按需开启监测。
4. 确认 v2 可正常工作后，才决定是否让 v2 接管开机启动。无需删除 v1。

更换电脑或 Windows 用户时应采用此方法。Windows DPAPI 密码保护通常绑定原 Windows 用户与原电脑，复制账号文件到其他环境可能无法解密。

## 同一电脑、同一 Windows 用户的定向复制

如需保留已存账号，仅在 **v1 与 v2 都已彻底退出、后台监测都已停止** 后操作：

| 来源 | 目标 | 说明 |
| --- | --- | --- |
| v1 的 `data/credential.xml` | v2 的 `app/data/credential.xml` | 仅复制，不改动源文件；文件含账号名及 DPAPI 加密密码，不应展示或分享。 |
| v1 的 `data/ui-settings.json` | v2 的 `app/data/ui-settings.json` | 可选；保留“打开助手时自动监测”等设置。 |

若目标已有账号或设置，先在本机保留目标备份并确认哪一份应生效，再复制。不要合并整个 `data/`，不要导入旧状态、运行日志或 `startup-backups/`；旧监测状态带有进程及目录身份，不能代表新副本的运行状态。不要复制 `CampusNetwork-Lens/state/` 的浏览器缓存和临时诊断；外观等浏览器内设置可能需要重新选择。

**首次打开的行为：** 没有有效设置时 `MonitorOnLaunch` 默认是 `true`。迁移账号而没有迁移设置，或者原设置已开启自动监测，都会使首次打开可能尝试认证。若希望先检查界面，可在复制账号前启动一次干净 v2，关闭“打开助手时自动监测”，完整退出，再只复制账号文件、保留 v2 自己的设置。也可在两边均退出时把目标设置里的 `MonitorOnLaunch` 明确设为 `false`，保持有效 JSON。

复制后只打开 v2，确认账号可读取。若不能解密，请直接在 v2 重新输入，保留 v1 原文件，不要尝试把加密文件转为明文或上传给他人。

## 开机启动与目录移动

v1 和 v2 共用当前 Windows 用户下名为 `CampusNetworkReconnect.lnk` 的启动入口。启用 v2 会在原入口可识别时替换为 v2；程序会在当前副本的数据目录保存必要的旧入口备份。无法识别的同名入口会被拒绝覆盖。

禁用操作只移除发起操作的副本拥有的启动项。因此 v2 接管后，在 v1 中点“禁用”不会删除 v2 的入口。切换之前先退出旧版；不要仅凭启动项已经替换就认定旧进程已退出。

程序身份包含安装目录和 Windows 用户，搬动或复制目录会产生新的运行身份与运行时发布目录。不要同时运行不同路径的副本。已注册开机启动时，搬动前从原目录禁用，搬动后从新目录重新启用。

## 回退

完整退出 v2 并停止其监测，再打开保留的 v1。若需要恢复开机启动，在 v1 中重新启用；它会按同样规则接管已识别的同名入口。v2 未自动改写 v1 的账号和设置，保留原目录可直接恢复原有配置。

只停止监测或清除本机账号不会主动注销当前校园网会话。是否仍在线需由后续认证状态检查确认。
